# 積木包的一生

> 一個包怎麼進來、怎麼更新、怎麼離開。這份文件只管這件事；
> 積木語意、manifest 格式、Host 邊界在 [`design.md`](design.md)。
>
> 狀態：**提案，全部未實作**。P3 第 2 步（從電腦匯入 `.zip`）已經落地，
> 這份文件寫的是它之後那幾步。**要做什麼、照什麼順序做，在最後一節。**

## 0. 現在壞在哪

右鍵刪掉一個擴充功能之後工具箱會卡住。那是症狀。
**成因是「刪除」有兩個意思，而選單只提供了其中一個，另一個沒有路。**

D31 的「刪除 = 從工具箱收起來，不動磁碟」在當時是對的：每個包都跟著 repo 來，
使用者沒有「裝」過任何東西。**匯入 `.zip` 做完的那一刻這句話就不成立了**——
他自己裝進來的包，現在唯一的移除方式是打開檔案總管，而那正是 P3 驗收句說
「全程不碰」的那個東西。

順帶一顆與設計無關的 bug：卡住多半是刪掉的正是**當時選著的分類**，而
`updateToolbox()` 之後那句 `refreshSelection()` 還指著它。規則補一條——
**刪掉的如果是目前選著的分類，先切回第一格**。

## 1. 三層帳，各一個動詞

「這個包在不在」被壓成一個問題，實際上是三個。

| 層 | 它說的是 | 存在哪 | 動詞 | 可逆嗎 |
|---|---|---|---|---|
| **磁碟** | 這台機器上有沒有這份程式碼 | `extensions/<id>/` | 安裝／解除安裝 | 要確認。刪掉的先進垃圾桶 |
| **工具箱** | 我現在想不想看到它 | `localStorage` | 加入／移除 | 隨時，零風險，不問「你確定嗎」 |
| **專案** | 這份畫布用到誰 | IR 的 `extensions` | —— | 不適用，它跟著畫布走 |

**最下面那一層一個動詞都沒有**：它是算出來的事實，不是使用者按得動的東西。
任何想「編輯專案用到哪些包」的介面都在對抗這件事。

規則：**下面一層不能超過上面一層。** 專案用到的一定在工具箱上（載入時取聯集，
已經有了）；工具箱上的一定在磁碟上（**現在沒有人守**，§0 那個洞住在那裡）。

三層一分開，D31 那條規則就從「一條規則」變成「一個位置」——它是第二層的動詞，
一直都是。缺的不是它做錯了什麼，是**第一層的動詞從來沒有被寫出來**。

## 2. 收據：這個資料夾是誰搬進來的

```
extensions/greet/.blockyard-source.json

{
  "origin":      "zip",             // official | zip | github | registry
  "label":       "greet.zip",       // 給人看的一行
  "url":         null,              // github / registry 才有
  "ref":         null,              // 分支或 tag
  "commit":      null,              // 真正裝進來的那一份
  "version":     "0.1.0",           // 裝的時候 manifest 說的
  "digest":      "sha256:9f2c…",
  "installedAt": "2026-09-04T16:59:12Z"
}
```

**不寫進 `manifest.yaml`**：那個檔案屬於包的作者。寫進去的話更新會整份覆蓋、
diff 從此不能看，而且**一個包可以謊報自己從哪來**——來源必須是安裝的人記的，
不是被安裝的東西自己說的。

**不放 SQLite，也不放一份總表**（`extensions/index.json`）。總表看起來方便，
但它把「這台機器上有哪些包」變成**兩個答案**——現在只有一個（`scan()` 讀資料夾），
而兩個答案一定會漂移：手動複製一個資料夾進去、直接砍掉一個、兩台機器各裝一個
再同步。更根本的是**來源是「這個包的性質」，不是「這次安裝的性質」**：
「這份東西來自 `github.com/x/y@abc123`」不管搬到哪台機器都還是真的。

VS Code 是先例：它確實有一份 `extensions.json`，但那是**可以從資料夾重建的快取**，
漂移了就重掃。所以——**收據是真相；總表如果有一天要有，它必須重建得出來**。
以現在的規模（`scan()` 本來就在開 N 份 manifest）那份快取一天都還用不到。

> 真正該有中央檔案的是另一個東西：**工具箱那份名單**現在存 `localStorage`，
> 換一個瀏覽器就沒了。那是 per-machine 的資料，而它是 Q15。

### 「官方」是一個來源，不是一種東西

兩件事被 `builtin` 這個字黏在一起了：

- **內建積木**（`control` / `data` / `operator`）**不是隨附的擴充功能，是這個語言
  本身**。沒有 `main.py`、沒有 venv、由直譯器直接執行——「解除安裝 `如果⋯那麼`」
  不是一個有意義的句子。這個分界要留，而且它跟信任無關。
- **那五個包**（`demo` `http` `openai` `discord` `panel`）**已經不是內建了**：
  `discover()` 現在就拒收寫 `builtin: true` 的包。它們唯一的特別之處是跟著 repo 來。

所以：**給它們一張 `origin: "official"` 的收據**。`demo` 因此變成拔得掉的，
它們也免費得到更新那條路，而「官方」從一種東西變成一個標記。這一改順手刪掉
「沒收據的不能解除安裝」對隨附包講不通的那個例外。

**但它逼出一個更大的決定**：那五個包住在 git repo 裡，而 `pip install` 之後
`extensions/` 會在 site-packages 底下——一個使用者不該寫、也不該從那裡刪東西的
地方。所以**擴充功能的家要搬到 `~/.blockyard/extensions/`**，官方包第一次啟動時從
wheel 鋪過去。**這要排在「解除安裝」之前**，不然第一版的解除安裝是在改使用者的
git working tree。順帶它修掉現在那個小歪：使用者裝的包會掉進 repo 裡。

### 核心規則：只解除安裝我們裝的

**沒有收據 = 使用者自己放的，我們不碰。** 那不是錯誤狀態——那是一個人正在那個
資料夾裡寫他自己的包，而替他刪掉一個他正在編輯的目錄，是這整份設計裡唯一一件
真的會弄丟東西的事。

`.blockyard-source.json` 是一張「這個資料夾是我搬進來的」的收據，
而**只有開收據的人有資格把它搬走**。

## 3. 一條管線，三個入口

```
  .zip 上傳  ┐
  GitHub URL ├→ 暫存目錄 → 審閱（＋更新時的差集）→ 建 venv → extensions/<id>/ ＋收據
  登記處     ┘

  手動放資料夾 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄→ 沒有審閱，也沒有收據
```

三個入口**只差第一步**（怎麼把 bytes 弄到暫存目錄）。
**多一個來源不該多一條驗證路徑**，不然「從 GitHub 裝的包比較少檢查」遲早是真的。

下面那條虛線是**刻意留著的**：寫包的人要能把資料夾丟進去就開始改。
它沒有收據，所以也不會被我們解除安裝——那兩件事是同一條規則的兩面。

## 4. 更新（§16 Q24）

跟第一次裝走同一條管線，唯一的差別是**畫布上已經有它的積木**，所以審閱多一段
差集。判準與刪除一致：**會讓畫布上的積木失去來源的動作，都要先說出誰會受影響。**

| 差集 | 怎麼辦 | 為什麼 |
|---|---|---|
| 少了一顆積木，**而畫布上有** | **擋** | 跟「還有 3 顆在用，不准刪」是同一句話。而且要一樣**可解**：滑到那幾顆去，再按一次跳下一顆 |
| 參數變了，**而畫布上有** | 警告後放行 | 那幾顆會多出填不了東西的空孔（Q21）。不該擋——使用者可能正是為了修那個包才更新——但必須在按下去**之前**說 |
| 沒人用到的變動 | 只說一聲 | 多三顆、少一顆沒人用的、換了封面 |

**順序不是「刪掉再裝」**：舊的先搬進 `~/.blockyard/trash/<id>-<時間>/`，任何一步失敗
就搬回來。這個垃圾桶同時是三件事的答案——更新失敗的退路、「更新完發現更糟」的
退路，以及**解除安裝的實作本身**（移除一個包就是把它搬進去，不是 `rm -rf` 一個
使用者可能還想要的目錄）。

**版本不釘。** IR 的 `extensions[].version` 記的是存檔時看到的版本，那是一個
**事實**不是一個**要求**；對不上就說一聲，不擋。理由：釘住需要「去哪裡拿那個版本」
的答案，而在 `.zip` 的世界裡那個答案不存在。有了 `commit` 之後才有得談。

## 5. 兩種刪除，一個選單

它們**不能都叫「刪除」**。用字要說出動的是哪一層。

| 選單上的字 | 動的是 | 問不問 | 誰看得到 |
|---|---|---|---|
| 從工具箱移除 | 名單 | 不問（畫布上還在用仍然擋） | 每一個包 |
| 解除安裝⋯ | 磁碟 | 要 | **只有有收據的** |

第二條的確認不是一句「你確定嗎」，是**把收據攤出來**：這個包 2026-09-04 從
`greet.zip` 裝的、v0.1.0、畫布上有 3 顆它的積木。那三個數字就是使用者需要的全部。

「畫布上還在用」對這一條的判準**更嚴**：移除只是收起來，解除安裝會讓那些積木
退化成 §13.3 的佔位符。

## 6. 從 GitHub 裝：六件只有它才有的事

1. **不 `git clone`，抓 tarball**（`codeload.github.com/<u>/<r>/tar.gz/<ref>`）：
   一個請求，不需要這台機器上有 git，也不用整段歷史。網址也接 `/tree/<ref>` 與 tag。
2. **tarball 一定多包一層**（`<repo>-<ref>/`）——這件事已經免費了，
   「對著資料夾按右鍵壓縮」那條規則處理的就是它。
3. **一個 repo 一個包**：規則是「repo 根要有 `manifest.yaml`」。monorepo 的
   `#subdir` **先不做**，等真的有人抱怨。
4. **這是編輯器自己在打外網**，不受 `permissions: [net]` 管（那條管的是積木包）。
   它是這個工具第一條自有出網路徑，UI 上要說得出現在要去哪裡抓。
5. **收據記 `commit` 不記分支名**：`main` 明天就不是今天那一份了。
6. **私有 repo 與 rate limit：token 進 keyring**，走 D28 已經有的那條路。先不做，
   但要確定它塞得進去——而它塞得進去。

## 7. 登記處

`extensions.blockyard.dev` 之於管線只是**第三個入口**，驗證那一段一個字都不會變。
它加的東西只有兩樣是別處拿不到的：**有誰存在**（可以逛）、以及**誰有資格叫
`http`**。

### 兩種模型，實際查過的

| | Obsidian | Blender |
|---|---|---|
| 登記處存什麼 | **只有地址** | **檔案本身** |
| 一筆長什麼樣 | `{id, name, author, description, repo}`——五個欄位 | `{id, version, archive_hash, archive_url, archive_size, license, tags, …}` |
| 程式碼在哪 | 作者自己 repo 的 GitHub Releases | `extensions.blender.org/download/sha256:<hash>/…`（**網址本身就是雜湊**） |
| 規模 | `community-plugins.json`，7,256 筆、2.1MB，一個檔案 | 有 API、有版本歷史 |
| 下架 | 另外兩張表（`-removed.json`、`-deprecation.json`） | index 最上層一個 `blocklist` |
| 上架 | 對那個 repo 發 PR（**PR 就是審核**） | 上傳 + 審核流程 |

### 決議：索引式，偷 Blender 三樣東西

**做索引式**，而理由不是「比較簡單」，是**它幾乎不是一個新東西**：§6 的
「從 GitHub URL 裝」做完之後，登記處只多了 metadata——沒有伺服器、沒有資料庫、
沒有登入，就是一個 git repo 裡的 JSON。**上架 = 一個 PR，而那順便就是審核。**

偷過來的三樣：

1. **`sha256`**。Obsidian 的模型裡作者可以把 tag 重指到別的 commit，`v1.2.0` 的
   意思就變了。索引裡放雜湊，版本才是不可變的——而 §2 的收據**已經有 `digest`
   這一格**，兩邊天生對得起來。
2. **`blocklist`**。索引式刪不掉別人的程式碼，但擋得住新的安裝、也警告得了已經
   裝的人。Obsidian 也有，只是拆成兩張表才做到。
3. **每筆一個 `schema_version`**，索引格式之後才改得動。

**不抄的**：把七千筆塞進一個 2.1MB 的檔案。前 200 個包這樣寫是對的，但要知道
天花板在哪。

**索引式唯一真的痛的地方**：作者砍掉 repo，那個包就從世界上消失了。但對這裡
**輕很多**——安裝是把檔案複製進 `extensions/<id>/`，所以**裝好的包從此不再依賴
上游**；砍掉只影響「新安裝」與「更新」，不影響任何人手上正在跑的東西。
順帶一個現實好處：**我們從頭到尾沒有代管過任何人的程式碼。**

**索引位址是一個設定值（URL），官方那份只是預設值。** 這樣「自架登記處」第一天
就免費成立（Blender 的 remote repositories 就是這個），而且官方那份不享有特權。

### 名字：現在就要決定，以後改不動

§13.1 說 opcode 永不變更，而 opcode 是 `<id>.<opcode>`——id 以後若變成
`<作者>/<名字>`，既有專案裡每一顆積木的 opcode 都會斷。所以「id 要不要扁平」
與 Q20／Q21 同一類：**有時效的決定**。

**傾向：id 保持扁平，登記處當名字權威，撞名在安裝那一刻擋下來**——那條路已經
存在（就是現在那句「已經裝過了」），只要讓錯誤訊息說得出這個名字屬於誰。

**登記處不會讓審閱畫面變得比較不必要。社群上傳只會讓它更必要。**

## 8. 沒答的

- **差集要算到多細？** 「參數變了」在 manifest 上分得出來，
  **「這顆積木的意思變了」分不出來**——而那才是更新真正危險的地方。
  目前的答案是「分不出來就不假裝分得出來」。
- **§16 Q3**：分享一份專案時要不要連來源一起帶？帶了對方就能一鍵裝上同一份，
  **而那等於一份專案檔可以叫別人的機器去下載並執行程式碼。** 做匯出之前要先答。
- **更新失敗、垃圾桶裡躺著一份舊的**——那個狀態要不要在 UI 上看得見？
  看不見的話它只是一個會長大的資料夾。
- **`origin` 的字彙表要封頂**（同 Q9 的 `ui`）：它只決定兩件事——卡片上的標記、
  以及我們可不可以移除它。多出第三個讀者時要回來看這一行。
- **誰審那些 PR？** §7 說「PR 就是審核」，而那在一個人的時候是對的、在第五十個
  包的時候不是。Obsidian 有一整組志工在做這件事。**這一題不必現在答**，但它是
  登記處唯一一個不能靠寫程式解決的部分。

## 9. 第一次打開時，工具箱上一個擴充功能都沒有

查過了：`enabled` 的第一次讀取是 `readPref('extensions.enabled', [])`——**空陣列**。
所以一個全新的使用者打開編輯器，工具箱上一個擴充功能分類都沒有。

這件事會咬到「三分鐘做一個 Discord bot」那種 demo，而且**原因不是它沒裝**
（它就在磁碟上），是**它不在工具箱上**——§1 的第二層，跟收據完全無關。

**修法不是「預設全部打開」。** 那正面撞上 D31 的理由：分類欄是 60px 寬的一直排，
每多一個沒人用的包，使用者每天要掃過的東西就多一格，而它永遠不會自己消失。

**修法是：demo 用一份專案檔出貨，不是一段說明。** `initEnabled` 已經在做這件事
了——載入專案時把 IR 的 `extensions` 與偏好取聯集（本來是為了「打開別人的專案不會
有積木卻沒有分類」寫的）。所以整條路已經蓋好了：

```
打開 demo 專案 → discord 自動出現在工具箱 → 點下第一顆積木
  → MissingSecretError → 執行紀錄上長出一顆「設定 Bot Token」
  → 點下去直接開到那一格，鎖定、游標就在值那裡（D28）
```

**這需要的不是新功能，是一份 `project.json`。** 唯一要新寫的是「開場載哪一份專案」
——而那與 §16 Q15（偏好放哪）是同一條線上的東西。
